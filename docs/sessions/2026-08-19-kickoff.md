# Sessão — 2026-08-19 — Kickoff do projeto

## Contexto

Pedido inicial: criar um programa para macOS (e Linux) que ajude a limpar espaço em
disco — temporários, caches de desenvolvimento (Python envs, node_modules, Gradle
cache, .next, cache do VS Code, cache do Xcode, builds antigas iOS/Android, caches
do Docker, Simulators iOS), dados do próprio sistema (logs etc.), e dados de
aplicativos específicos (Chrome, Edge, Teams, WhatsApp, Outlook, entre outros —
os "vilões" de espaço).

## Decisões tomadas

- **Plataforma**: app Electron/Tauri multiplataforma (não nativo Swift-only), para
  cobrir macOS **e** Linux com uma única UI.
- **Stack**: Node.js/TypeScript (Electron + React no renderer, Node puro no main
  process para operações de disco).
- **Nome do app**: **Limpa Tudo** (após descartar DevSweep por conflito de nome com
  app existente na App Store, e outras sugestões em português que não agradaram).
- **Escopo de dados**: incluir também dados nativos do próprio macOS — logs,
  crash reports, caches de sistema — além dos caches de dev e apps de terceiros.
- Diretório do projeto criado e renomeado: `~/apps/Glodzinski/LimpaTudo/`.

## Documentação produzida (`docs/`)

1. `00-visao-geral.md` — princípios de segurança (nunca remover automático, sempre
   Lixeira por padrão, whitelist de paths, checagem de processos ativos, dry-run
   obrigatório) e stack técnica.
2. `01-categorias.md` — catálogo de categorias: caches de dev (node_modules, venv,
   Gradle, Xcode DerivedData, Simulators, Docker, Homebrew, Cargo, Go, Maven,
   Composer, VS Code, JetBrains), dados/logs de sistema macOS, dados/logs de
   sistema Linux, apps vilões (referência ao doc 02), downloads/arquivos antigos
   (opt-in, alto risco). Inclui heurística de "projeto morto" (mtime antigo).
3. `02-apps-viloes.md` — catálogo de apps por categoria (navegadores, comunicação/
   colaboração, dev/produtividade, apps Apple, equivalentes Linux) com paths de
   cache por plataforma e nível de risco (🟢🟡🔴).
4. `03-arquitetura.md` — arquitetura Electron (main/renderer via IPC com
   contextBridge, sem `nodeIntegration`), módulos do main process (`platform/`,
   `catalog/`, `scanner/`, `processDetector`, `remover`, `reportGenerator`),
   módulos do renderer (React), contrato IPC de exemplo, plano de empacotamento
   (electron-builder: dmg + AppImage/deb) e estratégia de testes.
5. `04-fluxo-scan-e-remocao.md` — fluxo funcional completo: onboarding, scan
   (streaming incremental por categoria), seleção (pré-marcação por risco),
   confirmação (checagem de apps abertos, avisos de sudo), remoção (item a item,
   Lixeira por padrão), relatório final com opção de desfazer, e casos de borda
   (symlinks, volumes de rede/iCloud, permissões TCC do macOS).

## Sistema de risco definido

🟢 baixo (pré-selecionado) · 🟡 médio (desmarcado, exige confirmação extra) ·
🔴 alto (nunca no scan padrão, só em modo avançado explícito).
